# Retrieval evaluation

Compares plain vector retrieval with vector retrieval followed by a reranker,
so the decision to add a reranker rests on measured hits and not on a hunch.
It is a manual tool: it needs a local Ollama with the embed model and the
reranker model, and it is not run in CI.

```bash
make eval-retrieval          # synthetic corpus, results in evals/results/
```

## What it measures

For every question it retrieves the top **20** chunks by cosine similarity and
checks where the right chunk lands, before and after reranking the same 20:

| Column | Meaning |
|--------|---------|
| `pool` | questions whose right chunk is among the 20 candidates: the ceiling, since a reranker cannot rescue a chunk that was never retrieved |
| `hit@k` | questions with the right chunk in the first k results |
| `MRR` | mean of 1/rank of the right chunk within the pool |

A hit needs **both** the right document and the gold figure in the chunk text
(whitespace-insensitive), and the build fails unless each gold figure sits in
exactly one chunk of the corpus, in the question's own document.

It follows the production path where it matters: the project's PDF parser and
chunker with the `Settings` defaults, the `Settings` embed model, and the
prompt-safety escaping and length limits on everything that enters the
reranker prompt. It differs in one respect: ranking is an exact in-memory
cosine, not the pgvector HNSW index. The report records the Ollama version and
model digests, because both model tags float.

## How it is kept honest

- The questions are generated by `evals/synthetic.py` with a fixed seed and
  **committed** (`evals/questions/synthetic.jsonl`) so they can be reviewed; a
  test fails if the file drifts from the generator.
- Frozen before the first run and not tuned against the results: the pool size
  (20) and the two reranker instructions (`default`, the model card's example,
  and `task`, one sentence about annual reports).
- Two variants: `plain` (chunks as stored) and `titled` (the document title,
  from the file name, prepended to every chunk). Sections that never name the
  company or the year cannot be told apart by any ranker; `titled` shows how
  much of that is a context problem with a cheaper fix than a reranker.
- Results are reported per category, with counts, not only as an overall figure.

**The synthetic corpus and its questions were written by the project, so the
numbers are indicative only.** Switching a reranker on needs the same
evaluation on real documents.

## Using your own PDFs

Put the PDFs in `evals/data/real/` (git-ignored: financial documents can be
private, never commit them) and write a JSON-lines file next to them, one
question per line:

```json
{"id": "r01", "category": "revenue", "question": "What was revenue in 2024?", "document": "annual-report-2024.pdf", "gold": "USD 1,284 million"}
```

`gold` is a string that appears in exactly one chunk, the answer-bearing one;
`document` is that PDF's file name. Then:

```bash
uv run python -m evals.retrieval_eval --pdf-dir evals/data/real \
    --questions evals/data/real/questions.jsonl --label real \
    --variants plain,titled --instructions default,task
```

Pick questions where retrieval currently fails or is unsure; easy questions
only show that nothing needs fixing.
